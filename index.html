About Raj Thakur - Senior ML Engineer

I'm a Senior Machine Learning Engineer at AWS Neuron. Eleven years in software, the last four on LLM inference for AWS Trainium. I designed and built the disaggregated serving stack for vLLM on Trainium and started Neuron's move from PyTorch/XLA to native torch.compile.


These days most of my time goes into making models run faster and more accurately on Trainium: decode performance for GPT-OSS, multimodal models like Qwen3-VL, and multi-LoRA serving. I presented our out-of-tree vLLM plugin for Trainium at PyTorch Conference North America 2026.

LLM inference on AWS Trainium: disaggregated serving in vLLM, model performance and bring-up, and native PyTorch for Neuron

  • Designed and built disaggregated inference for vLLM on Trainium. Prefill and decode run on separate nodes, the KV cache moves device to device with NIXL over EFA, and a batched transfer API I added to the runtime doubled KV transfer throughput. It runs multi-node xPyD on EKS, including mixed GPU and Trainium.
  • Found why disaggregated decode stalled between steps: new input addresses forced the runtime to rebuild its DMA rings on every step.
  • Built a multi-agent C++ code-review workflow on Claude Code that has caught several bugs in the team's runtime changes, including a concurrency race in async KV-offload code.
  • Traced a decode-latency gap between native PyTorch and XLA on GPT-OSS-120B to two compiler inputs, one of them a small all-gather mis-tagged as FSDP. Correcting both brought native to parity in testing.
  • Explained a decode stall at 64-way expert parallelism. Request churn was backing up behind a CPU all-reduce that runs on every step.
  • Worked with the author of the multi-LoRA NKI kernel to speed up multi-LoRA decode. Profiling showed about half the HBM reads were repeat loads, and the static-slot decode path I designed shipped in the kernel.
  • Found the trigger for a GPT-OSS-20B accuracy regression (one compiler lowering for large KV writes) by replaying captured inputs across ranks, and validated the workaround.
  • Showed that a set of compiler accuracy bugs were the same kind of failure: no optimization level was safe for every graph.
  • Brought up GPT-OSS on native PyTorch for Neuron, fixing integration bugs until BF16 passed GSM8K on Trainium2 and Trainium3. Tracked an out-of-memory failure to missing KV aliases and fixed the index bug that dropped them, bringing accuracy in line with XLA.
  • Started the native PyTorch project for Neuron inference: torch.compile lowered through torch-mlir instead of PyTorch/XLA. Wrote the proposal to adopt it across the inference stack, then the proposal to retire PyTorch/XLA-based torch-neuronx in Neuron 2.32, which all 8 required approvers signed off.
  • Built device-free torch.compile for Neuron. I wrote and merged the compiler API (FX to StableHLO to NEFF) and a compile-only mode, so inference models compile on plain CPU hosts with no Trainium attached.
  • Got the first vLLM TP8 server running on native PyTorch for Neuron, then dogfooded 6+ state-of-the-art models on it, including GPT-OSS and Qwen3-VL.
  • Earlier: owned PyTorch upgrades across 10+ Neuron packages, moved the PJRT plugin to JAX 0.7.0, and built an HLO diff tool for compiler regressions.
