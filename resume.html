Removed each of those eight dependencies on device residency, including deferred runtime initialization, null-returning storage and allocator paths, no-op host copies, lazy stream creation, and a virtual device count. Confirmed the correction by SHA-256 match of the StableHLO output against the on-device path, and attributed the remaining NEFF byte difference to non-deterministic compression in the compiler rather than to a program difference.
  • Diagnosed and fixed an out-of-memory failure that blocked a large open-weight mixture-of-experts model on the native path. The compiler memory verifier double-counted in-place key-value cache tensors because the graph omitted output-to-input aliasing metadata, compounded by an operand-indexing defect in custom-kernel mutation detection. The fix restored end-to-end GSM8K accuracy parity with the XLA baseline at default memory utilization, and required no change to the model, kernels, or allocator.
  • Disproved a blocking assumption that PyTorch AOTAutograd prohibits shared-storage key-value caches. Established the actual constraint through on-device experiments, then validated a shared-storage layout that satisfies it, removing a 2x duplication of cache inputs.
  • Isolated an eight-way tensor-parallel decode hang to a stall inside the compiled graph on the device, rather than the suspected out-of-bounds access or rank divergence. Per-rank tracing confirmed all ranks executed identical step counts. The structural cause is that the native path emits one monolithic graph whose sequential collective barriers allow a single stalled operation to hang the entire parallel group, unlike the finer lazily-traced graphs XLA produces.
